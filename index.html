Register Method Repositories Journal

I test trading ideas until they break, and write down how.

Most of my repositories are failed hypotheses with the numbers left in. The rest is the infrastructure that keeps those tests honest: checked data, causal features, purged validation, hard risk limits.

A result only counts if the rules were written before it existed.

Every idea goes through the same steps. The point is not caution for its own sake: it is that every variant I try makes the next result less believable, so the number of trials has to be part of the answer.

  1. Pre-register. Rules, variants, costs, data split and decision rule are committed before any backtest runs.
  2. Implement and review. Code is written from the document alone, then checked against it and for look-ahead.
  3. Development gate. Trade count, stressed t-statistic, Deflated Sharpe, probability of backtest overfitting, fold stability.
  4. Holdout. Opened once, and only if the development set passes.
  5. Record. The result goes into the same document. It is not edited afterwards.

Six repositories, in the order a question travels.

Test counts are from local runs on a clean install. SIEVE, TRIAGE and Aethel are public. NQX, ICTraX and TFEX are private for now.

  1. SIEVEUS100 CFD, MetaTrader 5

    Is the data what I think it is?

    A read-only audit of server clock, DST eras, tick-level spread regimes and session changes, re-derived by an independent second implementation. Costs measured here feed every later test. Phase 2 tests ideas under a plan frozen first, with the 2026 holdout locked.

    Found
    The broker clock is London time with daylight saving, not a fixed offset. Stage A: 0 of 8 candidates passed.

    111
  2. NQXHypothesis register and gates

    Does the idea survive rules written before the test?

    The register above, plus the code that runs it: data ingest and quality checks, features, an experiment runner, and promotion gates that count every trial. Swap and spread explain most of the intraday and daily failures.

    Found
    An early report assumed a fixed UTC+1 server clock. It was wrong, shifted winter sessions by an hour, and its results could not be reproduced. The report is marked superseded in the repo.
  3. TRIAGETriple-barrier meta-labeling

    Does an ML filter add anything under strict validation?

    Rule-based candidates, first-touch labels on M1 bars, a LightGBM filter, purged splits, CPCV, a trial registry and a shuffled-label leakage check. Three phases, each ending in a written decision.

    Found
    Pooling three majors gave an out-of-sample AUC of 0.559. Widening to six symbols (10,232 events) removed it: AUC stayed near 0.51 and calibration came out flat. Phase 3 was rejected.
    Tests
    Suite passes on a clean install

    Can a discretionary method be made testable?

    Sweeps, structure breaks and fair value gaps as a deterministic state machine. Structure is frozen once confirmed, fills require price to trade through the entry, and tests deliberately try to leak the future. Includes a FastAPI backend and a Next.js dashboard.

    Where do language models belong in a trading loop?

    Behind a hard limit. An ML signal is reviewed by agents that can propose and veto but never size or relax a rule. A plain-Python risk gate fails closed, and execution has no model calls and runs once per decision. Shadow mode logs orders without sending them.

How I got here, including the parts that did not work.

Forex at university, then a bought EA

Believed
Someone sells an automated system that works.
What broke it
I paid for one in my first job and lost the money. I could not check any claim it made.
Changed
I started building my own, so I could inspect every step.

METEA: more indicators

Believed
RSI, stochastic, EMA and MACD together, tuned long enough, make a system.
What broke it
The backtest looked better than expected. Live, it did not. That is when I learned the word overfitting.
Changed
I began testing one hypothesis at a time. Converting TradingView strategies to MQL5 did not find anything either.

Janus: machine learning

Believed
A CNN-LSTM with an XGBoost meta-model and Kelly sizing, built over several versions, would find the edge.
What broke it
The backtest was spectacular. Live, it was not. Tracing why taught me look-ahead bias.
Changed
Results that look too good now start an investigation. Every feature has to be available at the moment of the decision, and I count every trial.

LLMs, then a harness

Believed
Language models could speed up the coding.
What broke it
Early on they were weak at MQL5 and I stopped using them. They improved.
Changed
I stopped asking for code and started working inside a harness: pre-registered hypotheses, tests, leakage checks, trial counts, real costs before anyone looks at a result. NQX came out of that.

What I took from it.

  1. A result that looks too good is a bug until shown otherwise.
  2. Every feature must be knowable at the time of the decision.
  3. Count every trial, then correct for them.
  4. Put real costs in before looking at an equity curve.
  5. Validate out of sample with purging, then believe it.

Research, not investment advice. Backtests describe the past under stated assumptions.
