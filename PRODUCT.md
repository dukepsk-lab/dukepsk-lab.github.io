# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack
Static HTML and CSS, no build step, published on GitHub Pages. Chosen so the site has no dependencies to rot and can be read without JavaScript.

## Users
Quant hiring managers, researchers and recruiters at funds and prop firms, reading on a laptop, usually after opening the GitHub profile. They have a few minutes and are skeptical of backtest claims.

## Product Purpose
The personal portfolio and research journal of dukepsk-lab, applying for Quantitative Researcher and Quantitative Developer roles. Success: a reader understands in a minute that this person tests ideas under pre-registered rules, reports failures honestly, and can build the infrastructure; and can find the repos behind it.

## Positioning
A portfolio whose main evidence is rejected hypotheses with the numbers shown, plus a journal of how the methodology was learned from early mistakes (an overfit EA, a look-ahead backtest). A retail-bot portfolio could not truthfully show this.

## Operating Context
Reads like a lab notebook: hypothesis register, method, results, journal. Links go to GitHub repos that are public; private ones are named but not linked.

## Capabilities and Constraints
- English copy. Thai is not used on the site.
- Some repos are private; links must not point at 404s. Link only public repos.
- Never mention or link any strategy that is running live, and do not include results that describe one.
- No performance claims that the repos do not record. Owner's real name and contact email are not confirmed: use the GitHub handle.

## Brand Commitments
Handle: dukepsk-lab. Direction chosen by the owner: research notebook.

## Evidence on Hand
NQX hypothesis register (69 variants, none promoted), SIEVE audit and pre-registered Phase 2, TRIAGE Phases 1 to 3, test counts (SIEVE 111, TFEX 224, ICTraX 88, Aethel 66, from local runs), MY_JOURNAL.md in the parent folder. No live trading results, no testimonials, no photo.

## Product Principles
1. Show the failure with the number next to it.
2. Every claim is traceable to a file in a repo.
3. Say what a repo does not contain (no results, stub adapter) as plainly as what it does.
4. The page is read, not performed: content first, ornament never.

## Accessibility & Inclusion
Readable without JavaScript, contrast at least 4.5:1, keyboard focus visible, respects reduced motion.
